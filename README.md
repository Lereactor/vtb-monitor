# vtb-monitor — оповещатель о сбоях ВТБ и ВТБ Мои Инвестиции в Telegram

Каждые 5 минут проверяет публичные детекторы сбоев и официальный Telegram-канал ВТБ
и присылает сообщение в Telegram, указывая сервис и источник.

## Что отслеживается

| Сервис | Детекторы | Официальный канал |
|---|---|---|
| **ВТБ** (банк, ВТБ Онлайн) | DETECTOR404, DownReport, DownRadar, СБОЙ.РФ | @bankvtb |
| **ВТБ Мои Инвестиции** | DETECTOR404, DownReport, DownRadar (`broker.vtb.ru`) | @bankvtb (посты про инвестиции помечаются) |

У каждого сервиса свой инцидент: сбой Инвестиций не смешивается со сбоем банка.
Список сервисов и страниц — в `monitor/services.py`.

## Как устроено

```
VPS 4VPS (Новосибирск, 193.233.84.69)
├── vtb-monitor.timer, каждые 5 мин  → проверка детекторов обоих сервисов
│                                      → сообщения через GitHub API → workflow «notify» → Telegram
└── vtb-channel.timer, каждые 5 мин  → запускает workflow «vtb-monitor» на GitHub
                                       → проверка канала @bankvtb → Telegram напрямую
```

С российского VPS Telegram (api.telegram.org и t.me) заблокирован, а DownRadar не пускает
серверы GitHub — поэтому проверки на VPS, а всё, что касается Telegram, на GitHub.

На VPS: код в `/opt/vtb-monitor` (пользователь `vtbmon`), состояние в `/var/lib/vtb-monitor/state.json`,
токен GitHub (fine-grained, только этот репозиторий, Actions: read/write) в `/etc/vtb-monitor.env`.

Каждое утро бот пишет, что работает; если на VPS осталось меньше 200 МБ, добавляет предупреждение.

Обновить код на VPS: `sudo -u vtbmon git -C /opt/vtb-monitor pull`.
Логи: `journalctl -u vtb-monitor -n 50`.

Повторный запрос к тому же сайту идёт после паузы 5 секунд: DownRadar начинает отвечать
таймаутом на запросы подряд.

Не используются:
- **Downdetector** — закрыт Cloudflare-проверкой, условия запрещают парсинг (легально — платный Enterprise API).
- **СБОЙ.РФ для Инвестиций** — страницы для «Мои Инвестиции» на нём нет.
- **неработает.рф** (`/vtb`, `/investicii-open`) — только «жалоб за 24 часа» без вердикта, и жалоб единицы
  (5 у ВТБ и 1 у Инвестиций за сутки, против 150–300 у ВТБ на других сайтах); свежие комментарии — апрель и август 2026.
- **downdetector.info** — домен припаркован: по HTTPS не отвечает, по HTTP — заглушка регистратора «NameBright — Coming Soon».
  В поиске он виден по старой копии страницы.
- **@vtbmyinvestments** — сейчас это чужой пустой канал «тест 123», а не официальный канал брокера.

## Сообщения

Каждое сообщение начинается с названия сервиса: «ВТБ» или «ВТБ Мои Инвестиции».

- 🔴 **похоже на сбой** — первый сайт показал сбой (с цифрами, ссылкой и «Сбой видят сайтов: 1 из 4»;
  пока он один, сообщение предупреждает о возможной ложной тревоге)
- 🔴 **сбой подтверждает ещё один сайт** — к сбою присоединился ещё один сайт («2 из 4»).
  Считаются только работающие сайты: сломанный в знаменатель не входит
- ✅ **всё в норме** — 2 прогона подряд ни один сайт сервиса не видит сбоя, с длительностью
- 📢 **ВТБ официально сообщает** — пост из канала банка
- ⚠️ **перестал отвечать** / ✅ **снова отвечает** — сайт не отвечал 30 минут (6 прогонов) подряд или снова
  заработал. В сообщении статус всех проверок (✅/❌) и есть ли сейчас сбой, чтобы было видно,
  что сломался только один сайт. Одиночные ошибки в чат не пишутся, только в лог
- ☀️ **утренний отчёт** — раз в сутки после 9:00 МСК, в том же формате: все проверки и есть ли сбой.
  Нет отчёта — значит, сломался сам оповещатель.

## Настройка

1. **Бот:** в Telegram напишите [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен.
2. **chat_id:** напишите своему боту любое сообщение, откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и возьмите `message.chat.id`.
3. **Секреты:** Settings → Secrets and variables → Actions → New repository secret:
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
4. **Проверка:** Actions → vtb-monitor → Run workflow → галка «Отправить тестовое сообщение».

## Сайт

**https://lereactor.github.io/vtb-monitor-live/**: статус сейчас, лента сбоев, аналитика.
Раздел «Техника» (все проверки, простои сайтов-мониторов, сообщения в чат) открывается паролем.

- Каждая проверка на VPS пишется в `/var/lib/vtb-monitor/history.db` (SQLite). Из неё собираются
  `public.json` и зашифрованный `private.enc` (AES-GCM, ключ из пароля через PBKDF2, 600 000
  итераций). Оба файла уходят force-push'ем в ветку `data` репозитория `Lereactor/vtb-monitor-live`.
  Браузер читает их с raw.githubusercontent.com и расшифровывает закрытую часть сам.
- Ошибки истории и сайта только пишутся в лог (`history: …`, `site: …`), оповещения не задерживают.
- Настройки в `/etc/vtb-monitor.env`: `SITE_REMOTE`, `SITE_DEPLOY_KEY`
  (`/var/lib/vtb-monitor/site_deploy_key`, ключ развёртывания только для этого репозитория),
  `SITE_KEY`, `SITE_SALT`, `SITE_ITER`. Пароля на VPS нет, только ключ. Сменить пароль:
  удалить три строки `SITE_KEY`/`SITE_SALT`/`SITE_ITER` и выполнить
  `python scripts/derive_site_key.py | ssh root@vps "tr -d '\r' >> /etc/vtb-monitor.env"`.
- Код сайта в `site/` (React + Vite). Выложить: `cd site && node scripts/build-site.mjs --deploy`.
  Для разработки: `python scripts/make_sample_data.py --db … --state …`, потом `npm run dev`
  (пример данных с паролем `test`, в сборку не попадает).

## Ограничения

- `state.json` публичный (репозиторий открытый): в нём только статусы источников.
- `t.me/s/` показывает ~20 последних постов: если оповещатель долго не работал, старые посты могут быть пропущены.
- DETECTOR404 и DownRadar стоят за защитой от DDoS (QRATOR, Cloudflare) и могут отвечать
  ошибкой или таймаутом — тогда через 30 минут придёт ⚠️ «перестал отвечать».
- Пороги (10 жалоб/час DownRadar, 50 жалоб/час СБОЙ.РФ) подобраны по обычным дням, на настоящем
  крупном сбое ещё не проверены.
- Жалобы пользователей ≠ подтверждённый сбой. Официальное подтверждение — только 📢 от банка.
